# QDsssp 性能检查与实机对比（2026-10-02）

已完成组件优化、RK3506 实机对比及部署。优化版正在 `root@192.168.123.100` 上以默认 PCM 频谱、30 fps 运行，程序为 `/opt/qdsssp/bin/qdsssp_demo`。

正式三轮测试中，PCM + 静态 EQ 的进程 CPU 占用从单核的 **26.404% 降至 17.803%（降低 32.6%）**；2048 点频谱分析平均耗时从 **0.512 ms 降至 0.339 ms（降低 33.8%）**。合成频谱静态场景 CPU 降低 25.6%，持续 EQ 编辑场景降低约 5%～7%。各场景保持约 30 fps，所有 PCM 对比均无丢样本。

## 检查与实现

| 路径 | 检查结论与处理 |
| --- | --- |
| EQ 响应计算 | 已缓存频率网格三角函数，按脏段计算并增量汇总，256 次更新后重新求和；常量响应和重复参数已有快速路径。保留双精度复数计算，避免低频、高 Q 下的消减误差。 |
| 曲线和阴影 | 已按 0.2 物理像素误差压缩折线，动态编辑直接绘制，静止后生成覆盖层缓存。试验 `drawPolyline` 没有稳定收益，且部分 AA / DPR 场景图像不同，因此保留 `drawPath`。 |
| 背景、控制点和底栏 | 已有背景及标记位图缓存、底栏依赖比较、局部更新和准备快照；本次保持这些实现。 |
| 频谱投影和调度 | 已有峰值保留桶、最多 512 显示点、latest-only 邮箱、合并刷新、绝对帧截止时间和静止不重绘。保持采样密度、释放速度与帧率限制。 |
| 频谱重绘 | 原版只要频谱改变就刷新整个绘图区；改为刷新新旧频谱路径覆盖范围的并集，减少背景及覆盖层合成。开启面积填充时，范围包含到底噪基线的区域。 |
| 音频 FFT | 原版对纯实数输入执行 N 点复数 FFT，每帧重新计算排列及递推旋转因子；改为复用预计算计划，执行 N/2 点复数 FFT 后恢复实数输入的单边谱。 |
| 采集和线程 | 保留 SPSC 环形缓冲、暂停时维护最新窗口和代际发布校验；未调整轮询间隔、文件读取节奏或音频 hop。 |

`src/spectrum_fft.h` 中的内部 `SpectrumFft` 同时供 PCM 和 PipeWire 使用。启动时准备周期 Hann 窗、位反转排列和旋转因子；加窗时直接把偶数、奇数样本写入排列后的复数数组，执行半长度蝶形运算，再恢复包含 DC / Nyquist 的单边功率谱。

保持 `N/2+1` 个输出、频率和幅度 dBFS 归一化及 −120 dB 底噪。没有使用近似对数或 `fast-math`。分析线程复用计划和输出容量，每帧不分配 FFT 临时数组。2048 点计划在 32-bit ARM 上比原实现多使用约 4 KiB 数组空间。

`EqWidget::frameTick()` 在重建频谱前后计算路径边界并合并，包含线宽、取整和设备像素比所需的余量。旧范围保证回落的峰值能被擦除；填充范围延伸到绘图区底部。尺寸变化、填充切换和频谱开关仍通过现有完整失效路径处理。

## 实机测试条件

| 项目 | 配置 |
| --- | --- |
| 板子 | Luckfox RK3506，3 个 Cortex-A7 核心，ARMv7 / NEON / VFPv4 |
| 系统 | Linux 6.1.99，Qt 5.15.19，板上原有 `/usr/lib` 运行库和 linuxfb 插件 |
| 构建 | Release，Buildroot GCC 12.4，现有 `cmake/rk3506-toolchain.cmake`；原版和优化版参数一致 |
| CPU | 正式对比的主线程和音频线程均继承 `taskset -c 0`；读取的 armclk 为 1.2 GHz，未修改时钟 |
| 显示 | framebuffer 800×480、32 bpp；窗口 800×480，组件 800×424 |
| 负载 | 32 个 EQ 段，EQ 抗锯齿开启，频谱线不抗锯齿，面积填充关闭 |
| 频谱 | 合成输入 8193 点；PCM 为仓库的 DOGFIGHT.pcm，44100 Hz、2048 点 FFT、1024 点 hop，实际输出 1025 点 |
| 采样 | 每个场景原版 / 优化版各 3 次；每次预热 60 次输入、测量 300 次，保留原有的 100 ms 排空时间；第 2 轮交换版本顺序 |

首次未绑定 CPU 的测试中，未修改的 EQ-only 对照也出现明显波动，因此正式对比将两个版本固定在同一核心上重复三轮，减少核心迁移与调度差异。正式运行的演示程序允许使用全部 3 个核心，没有保留测试时的 CPU 绑定。

CPU 百分比为整个进程的 CPU 时间除以测量墙钟时间，100% 表示占满一个核心。下表均为三次运行统计量的中位数；P95 为各次运行 P95 的中位数，没有把不同运行的帧合并计算。基准程序未修改。它原有的 `bins=8193` 字段描述合成数组，在 PCM 场景中不代表 FFT 输出点数。

## 30 fps 正式对比

| 场景 | 原版 CPU（单核 %） | 优化 CPU（单核 %） | CPU 变化 | 原版 / 优化绘制 fps |
| --- | ---: | ---: | ---: | ---: |
| 合成频谱 + 连续 EQ 编辑 | 50.089 | 46.631 | −6.9% | 29.800 / 29.797 |
| 合成频谱 + 静态 EQ | 22.787 | 16.957 | −25.6% | 29.795 / 29.796 |
| PCM + 连续 EQ 编辑 | 55.181 | 52.454 | −4.9% | 29.883 / 29.887 |
| PCM + 静态 EQ | 26.404 | 17.803 | −32.6% | 29.883 / 29.884 |
| EQ 编辑，无频谱源 | 41.440 | 41.588 | +0.4% | 29.796 / 29.797 |
| 每 tick 四帧合成频谱 | 54.107 | 50.631 | −6.4% | 29.997 / 29.996 |

FFT 计时包含加窗、排列、变换及 dBFS 换算：

| PCM 场景 | 原版平均 ms | 优化平均 ms | 降幅 |
| --- | ---: | ---: | ---: |
| 连续 EQ 编辑 | 0.511 | 0.340 | 33.5% |
| 静态 EQ | 0.512 | 0.339 | 33.8% |

绘制与准备阶段的变化并不完全一致：

| 场景 | 准备 P95 ms，原版 → 优化 | 绘制平均 ms，原版 → 优化 | 绘制 P95 ms，原版 → 优化 |
| --- | ---: | ---: | ---: |
| 合成频谱 + 连续 EQ 编辑 | 3.486 → 3.522 | 8.261 → 7.926 | 9.039 → 10.011 |
| 合成频谱 + 静态 EQ | 0.549 → 0.580 | 2.982 → 2.338 | 3.139 → 2.503 |
| PCM + 连续 EQ 编辑 | 4.585 → 4.302 | 9.180 → 8.749 | 10.639 → 11.040 |
| PCM + 静态 EQ | 0.462 → 0.507 | 3.415 → 2.276 | 4.488 → 2.897 |

静态 PCM 的绘制 P95 降低 35.4%。计算刷新范围增加了少量准备工作；动态编辑场景的绘制 P95 增加约 4%～11%，平均绘制耗时和进程 CPU 仍下降，软件绘制 fps 保持不变。优化收益主要是降低持续频谱显示的 CPU 消耗，不能据此承诺所有阶段的尾部耗时都降低。未经过这两处优化的 EQ-only 场景基本不变，是本次测试的对照。

36 次正式运行全部正常退出，12 次 PCM 运行全部 `pcm_dropped_samples=0`。这些是 linuxfb 实机进程和组件计时；`paint_fps` 不包含面板扫描或触摸到显示延迟。

## 60 fps 补充压力测试

使用同一组二进制、相同 CPU 绑定及预热 / 测量次数，每个场景每个版本额外运行一次。该组为补充观察，不是三轮中位数。

| 场景 | 原版 / 优化 CPU（单核 %） | 原版 / 优化绘制 fps | 原版 / 优化 FFT 平均 ms |
| --- | ---: | ---: | ---: |
| 合成频谱 + 连续 EQ 编辑 | 96.907 / 89.856 | 58.374 / 57.872 | — |
| PCM + 连续 EQ 编辑 | 98.737 / 96.770 | 57.320 / 59.274 | 0.511 / 0.341 |
| PCM + 静态 EQ | 49.709 / 35.439 | 59.893 / 59.883 | 0.511 / 0.341 |

PCM 静态场景 CPU 降低 28.7%，所有 PCM 压力运行均无丢样本。32 段持续编辑在单核上已接近满载，优化版也没有在所有场景达到配置的 60 fps；正式演示保持默认 30 fps。

## 功能验证与部署

- 本机与实体板 Release 完整 QtTest 均通过：20 个测试方法，加上初始化 / 清理，共 **22 passed，0 failed，0 skipped**。
- FFT 独立双精度 DFT：256 / 512 点比较全部单边频点；1024～16384 点检查 DC、低频、内部频点及 Nyquist 边界，误差小于 0.01 dB。每个尺寸覆盖 0、1、N−3 三种环形起点。
- 复用 FFT 计划后，静音输出精确为 −120 dB；DC / Nyquist / 单频幅度误差小于 0.0001 dB。
- 频谱刷新测试逐像素比较前后完整图像，检查每个变化像素都包含在实际安排的重绘区域内，覆盖填充开关、峰值回落、数据过期及频谱关闭 / 恢复。本机额外验证 1.5× 和 2× 缩放，实体板验证 1×。
- ARM 交叉编译通过，实体板的数值、PCM 发布、并发和交互回归测试通过。实机性能结论使用原生执行数据。
- 板端没有运行 PipeWire 音频服务，因此实机音频对比使用 PCM；PipeWire 与 PCM 共用本次验证的 FFT 代码，未进行实时 USB / PipeWire 采集性能测试。
- 已安装程序和 PCM，校验 SHA-256 与测试版本一致；使用默认路径生成板端截图并检查频谱、曲线、控制点及布局。正式程序由 `nohup` 启动，允许 CPU 0～2，启动 PID 记录在 `/tmp/qdsssp-demo.pid`，日志为 `/tmp/qdsssp-demo.log`。

正式部署文件：

```text

/opt/qdsssp/assets/DOGFIGHT.pcm
```

当前已启动的程序供交互检查；本次没有新增开机自启配置。板上原有的文泉驿 Fontconfig 配置会输出一个警告，两个版本相同，截图中文字显示正常。
