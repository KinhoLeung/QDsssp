# QDsssp 追加性能优化与实机对比（2026-10-03）

本次以用户确认时的工作区代码为基线，包含 2026-10-02 已实现的实数 FFT 和频谱局部重绘优化；没有使用更早的 `e118b9a` 版本重新计算累计收益。优化重点是 EQ 编辑时的底栏与重复失效。

## 最终实现

- **底栏局部刷新**：文字、图标、Q 控件分别累积实际改变的区域。仅频率变化时不刷新 Q 行；显示文字未变化时不安排文字重绘。Q 移动只清除旧、新滑块之间的区域，再在该区域内绘制完整轨道和新滑块，保持原有圆角及抗锯齿效果。
- **底栏文字与字体复用**：保留调整后的 13 px 字体；宽度足够且测量字体一致时，用同一次 `QTextLayout` 排版同时检查宽度并绘制，覆盖原先 `elidedText()` 与 `drawText()` 的两次排版。可能需要省略、字体不同或显式 RTL 的布局仍使用原处理。文字布局由独立的逐像素原实现对照验证。
- **有效响应缓存**：缓存各段的有效常量或 biquad 系数。旁路、零增益 Peak / shelf、Gain 的频率 / Q 更新以及外部系数的元数据更新，复用已经准备的响应。变化的模型参数、控制点、外部系数提示和底栏仍更新。各段响应版本用于决定是否重建选中段路径；总路径仅在数值缓存实际更新或重新汇总时重建。网格 / 采样率变化会失效全部响应缓存。
- **控制点绘制**：动态绘制时，跳过不与当前实际重绘区域相交的控制点；静态覆盖层生成仍包含全部控制点，并保持原有绘制顺序。

保持原有双精度频响计算、EQ 采样数量、0.2 物理像素路径误差、抗锯齿、阴影效果、帧率限制、FFT / hop 和输入事件行为。ARM 上新增响应缓存字段约 1.7 KiB，字体缓存的实际内存成本通过进程峰值 RSS 观察。

## 筛选中撤回的方案

尝试把 EQ 曲线及阴影覆盖范围分为八个横向列，并将控制点的新旧区域分别加入刷新区域。修正了 1.5× DPR 下矩形裁剪的取整边界后，该实现通过了像素覆盖测试；但 ARM 软件绘制中的区域计算与裁剪成本抵消了面积减少的收益。

180 次测量的初步 PCM 动态对比中，6 段 CPU 为 42.933% → 44.356%，32 段为 52.320% → 54.229%，分别增加 3.3% / 3.6%。因此最终恢复原有曲线包围矩形刷新，保留底栏的独立局部刷新。该组属于候选筛选，不用于最终收益结论。

## 正式测试方法

- 板子为 `root@192.168.123.100` 的 RK3506；Qt 5.15.19、linuxfb、800×480 窗口、800×424 组件。
- 基线与优化版使用同一个新增可选段数参数的基准驱动、相同 Release / Cortex-A7 编译选项、相同 PCM、FFT、hop 和绘制设置。
- 6 段使用演示的棚式首尾段与普通 Peak 段；32 段为压力负载。动态场景更新同一个选中段的频率、增益和 Q。
- 正式 30 fps 测试覆盖合成动态 / 静态、PCM 动态 / 静态、EQ-only、四帧突发输入，共 72 次运行。60 fps 补充覆盖合成动态、PCM 动态 / 静态，共 36 次运行。
- 每个场景、段数和版本各三次；预热 60 次输入、测量 300 次输入，交替版本顺序。两个版本及其音频线程均继承 `taskset -c 0`，正常部署取消该绑定。
- CPU 百分比为整个进程的 CPU 时间除以墙钟时间，100% 代表占满一个核心。阶段耗时为墙钟；`prepare`、`paint` 等包含嵌套阶段，不能重复相加。
- 表中的 CPU、耗时和分位数均为三次运行统计值的中位数；P95 / P99 没有跨运行合并样本。软件 `paint_fps` 不包含面板扫描或触摸到显示延迟。

36 次补充运行正常退出，24 次 PCM 运行全部无丢样本，FFT 平均仍约 0.34 ms。

## 零增益调 Q 补测

使用同一个独立测试驱动，分别链接已测试的基线 / 优化组件库；32 段均为零增益 Peak，频率固定，更新选中段 Q，频谱关闭，窗口与组件尺寸保持 800×480 / 800×424。该场景的实际频响恒为 0 dB，Q 数值与滑块仍持续更新。驱动源码保存在 `build-performance-next/unity-q-probe/`，没有改变正式演示的基准行为。

| 项目 | 基线 | 优化 |
| --- | ---: | ---: |
| CPU（单核 %，三轮中位数） | 19.844 | 9.809 |
| 软件绘制 fps | 29.797 | 29.797 |
| 准备 P95 ms | 2.403 | 1.674 |
| 绘制平均 ms | 1.135 | 0.343 |
| 绘制 P95 ms | 1.201 | 0.357 |
| 峰值 RSS KiB | 17696 | 18716 |

该明确场景 CPU 降低 **50.57%**。优化版三次运行均 `response_evaluations=0`，路径 / 曲线阶段均无重建或绘制样本；绘制吞吐保持不变。此收益针对频响不变的 Q 更新，不能替代普通增益 / 频率编辑的 2.98%～5.05% 结果。

该补测启动后立即连续编辑，基线未进入静态覆盖层缓存，优化版则复用静态缓存；中位峰值 RSS 增加约 1.00 MiB。它属于组件已有静态位图缓存的成本，和普通动态场景的 −112～+156 KiB 变化分开报告。
